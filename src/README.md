2. 入力値（120, 0, 3）が届いた際の新旧パース処理の違い

・【Aモード】テキストファイル読み込みの場合（デモ用）
  - データの正体：ファイルから "120, 0, 3" という長い1本の「文字列テキスト」が届きます。
  - 内部の処理：文字のままだと計算できないため、カンマで切り分ける（.split）処理や、数値に直す重たい変換処理（.parse）を行う下準備が必要です。

・【Bモード】Linuxのコマンド送信の場合（実車テスト用）
  - データの正体：Linuxの別ターミナルから送信され、回線上を流れる生の「バイナリデータ（16進数）」が届きます。
  - 内部の処理：16進数の電気信号 0x78 が10進数の数値 120 として綺麗に分かれた配列のまま直接プログラムに命中。文字切り分けも数値変換も一切不要になり、数マイクロ秒という超高速でそのまま足し算（120 + 120.0 = 240 km/h）やビット演算へと流し込める、極めて効率的な低レイヤ設計です。

3. 【初めて実施する人向け】Linuxパケット送信テスト（Bモード）の完全手順書

・【事前準備】プログラムのスイッチを切り替える
  - VS Codeで `src/main.rs` の45行目付近にあるスイッチ変数を true に書き換えて上書き保存します。
    let use_real_can = true;

・【ステップ1】画面1を作成し、プログラムを「待ち受け状態」にする
  1. MacのVS Code下部にある黒いターミナルを1回クリックします。
  2. コマンド「orb」を入力して Enter を押し、Linux（arakawa@ubuntu）の環境へ入ります。
  3. 起動コマンド「cargo run」を入力して Enter を叩きます。
  4. ➔ 画面に「常時待ち受け中...」と表示されて静止します。この画面はそのまま開いておきます。

・【ステップ2】画面2を新しく開き、送信コマンドを撃ち込む
  1. プログラムが待機している画面1をマウスでクリックして選択します。
  2. キーボードの「Command + N」を同時に押し、新しく2枚目の黒い画面（画面2）を右側に開きます。
  3. 画面2の中に、以下のパケット送信コマンドを貼り付けて Enter をドンと叩きます。
     cansend vcan0 000#780003

・【ステップ3】リアルタイムの検知・連動を確認する
  - 画面2で Enter を叩いた瞬間、画面1のRustプログラムが目覚め、大勝利のパースログがドカンと出力されます！
    📈 現在の車速: 240 km/h / 🛑 ブレーキ状態: OFF / ⚙️ 現在のシフト: D (ドライブ) / [警告] 速度超過！

・【パケット（000#780003）の構造解説】
  - 000 : CAN ID（データ識別ヘッダ）
  - 78  : 1バイト目（車速生値）。16進数 0x78 は10進数で 120。ゲイン120.0を足して 240 km/h にパース。
  - 00  : 2バイト目（ブレーキ生値）。最下位ビットが 0 のためブレーキは OFF。
  - 03  : 3バイト目（シフト位置）。下位2ビット（0x03）のマスク検知により D（ドライブ）レンジにマッピング。
